# НашеПО · Поиск для Топоматик 360

Версия 0.6.0. Сквозной поиск по всему проекту. Введите любое значение, и плагин найдёт элементы во всех моделях проекта и подключённых вложений, подсветит их и переведёт камеру. Знать, в каком файле и в каком свойстве лежит значение, не нужно.

## Установка

Адрес плагина:

    https://borismoniac.github.io/360.info/

В настольном Топоматик 360 откройте **Плагины → Установить плагин**, вставьте этот адрес и подтвердите установку. После первой установки перезапустите приложение. В веб-версии обновите страницу.

[**Открыть установку в веб-версии Топоматик 360**](https://360.topomatic.ru?extensionInstallPath=https%3A%2F%2Fborismoniac.github.io%2F360.info%2F)

## Как пользоваться

Панель живёт в левом блоке **НашеПО**, вкладка **Поиск**. Открыть её можно и кнопкой **Поиск** на вкладке ленты **НашеПО**.

- Введите значение и нажмите **Найти** или Enter. Поиск идёт по имени элемента, по пути в дереве, по имени типа и по всем названиям и значениям свойств. Предела на число находок нет.
- Щелчок по строке списка подсвечивает этот элемент и переводит к нему камеру.

Под условиями отбора идёт ряд кнопок. Наведение показывает подсказку.

| Значок | Что делает |
| --- | --- |
| ‹ и › | Переход по находкам по одной, камера следует за выбранным |
| Выделить всё | Подсветить все находки и подогнать камеру под них |
| Снять выделение | Убрать подсветку |
| Прицел в рамке | Изолировать найденные: оставить видимым только список |
| Прицел | Изолировать выбранный элемент |
| Перечёркнутый глаз | Скрыть элементы из списка |
| Глаз | Показать всё скрытое в проекте |

Кнопка **Быстрый поиск** на ленте спрашивает значение и сразу подсвечивает все совпадения, без открытия панели.

## Поиск в одном параметре

Под строкой поиска стоит переключатель **искать**. По умолчанию там написано «везде», и поиск идёт по всему: имени, пути, типу и всем свойствам.

Щелчок раскрывает список параметров, сгруппированный по наборам. Сверху поле фильтра: наберите часть имени, и список сузится. Щелчок по строке применяет параметр и сразу запускает поиск. Если нужного имени в списке нет, наберите его и нажмите Enter — искать будет по тому, что набрано, годится и часть имени.

Список имён запоминается между запусками, поэтому после первого поиска он доступен сразу. Кроме свойств модели в нём есть имя, модель, путь и тип элемента: это поля самого элемента, и поиск по ним работает так же.

Если параметр указан, а значение не введено, плагин найдёт все элементы, у которых этот параметр заполнен. Условия отбора работают поверх результата в любом случае.

## Видимость элементов

**Скрыть** прячет все элементы текущего списка, уже после условий отбора. Видимость — это свойство слоя, и оно наследуется, поэтому скрытие узла убирает и всё, что внутри него.

**Изолировать** оставляет видимым только нужное. Одна кнопка изолирует весь список находок, другая — выбранную строку. Остальное скрывается. Поскольку видимость наследуется, плагин прячет не каждый лишний слой по отдельности, а целую ветку там, где внутри неё нет ничего нужного. На большой модели это разница между тысячами операций и десятками.

**Показать всё** возвращает видимость всему скрытому в проекте и во всех загруженных вложениях, независимо от того, кто это скрыл. Это же действие отменяет изоляцию.

Рядом с видимостью в дереве проекта стоит замок. Это другое свойство, `disabled`: слой не просто прячется, а замораживается и выключается из работы вида. Плагин его не трогает.

## Свойства элемента

Под списком находок лежит блок **Свойства элемента**. Он показывает все свойства выбранной строки, разложенные по группам: сначала имя, модель и путь, затем наборы свойств модели. Переключаться на штатную панель свойств не нужно, поэтому запрос и список находок не теряются.

Импортёр IFC складывает имя набора свойств и имя параметра в один ключ через вертикальную черту, например `МОГЭ_Геометрические параметры|Длина`. Плагин разбирает такие ключи и показывает набор заголовком, а под ним параметр и значение.

Выбор элемента прямо в модели тоже отображается в этом блоке: панель слушает событие выделения и показывает свойства выбранного элемента с пометкой. Если элемент есть среди находок, панель встаёт на его строку в списке.

Поле **фильтр свойств** оставляет только строки, где искомое встречается в названии или значении свойства. Заголовок блока сворачивает его, когда нужно больше места под список.

## Условия отбора

Блок **Условия отбора** сужает уже найденное, не запуская поиск заново. Кнопка ＋ добавляет условие.

Условие состоит из свойства, оператора и значения. Список свойств сгруппирован по наборам: заголовком идёт набор, внутри короткие имена параметров. Кроме свойств модели доступны имя, модель и путь, а вариант **любое свойство** проверяет условие по всем значениям сразу.

Операторы: содержит, не содержит, равно, не равно, больше, меньше, заполнено, пусто. Числовые сравнения работают и с запятой в качестве разделителя.

Условия складываются: элемент остаётся в списке, только если проходит все. Список пересобирается сразу при изменении любого условия.

Поле значения подсказывает, что это свойство принимает у найденных элементов: список готовых значений раскрывается по щелчку, а можно просто начать печатать, в том числе часть значения. Под полем видно, сколько всего разных значений известно.

Пока значение не введено, условие не применяется и подсвечивается подсказкой. Иначе список пустел бы сразу после выбора оператора. Для сравнений «больше» и «меньше» число вынимается из текста, поэтому значения вида «1 200,5 мм» сравниваются правильно.

## Настройки поиска

- **Учитывать регистр** включает точное совпадение регистра букв.
- **Искать в скрытых** добавляет к поиску скрытые вложения. По умолчанию они пропускаются, как и в штатных фильтрах программы.

## Как это устроено

Элементы моделей IFC и SMDX попадают в чертёж как слои с типизированными свойствами. Плагин обходит слои главного чертежа и чертежей всех загруженных вложений, сравнивая запрос с именем, путём, типом и всеми свойствами.

Подсветка и перевод камеры выполняются напрямую: у слоя вида вызывается `selectObjects`, а границы выделенного собираются тут же, в предикате, и передаются камере.

Штатный `selectLayers` для этого не годится. Он только рассылает событие, а выделяет и подгоняет камеру панель дерева проекта. Когда открыта панель поиска, дерево скрыто, обрабатывать событие некому, и переход срабатывал через раз.

Список свойств очищен от служебного. Не показываются поля самого слоя: видимость, заморозка, цвет, вес линии, печатность, имя и ключи. Не показываются и пустые значения: параметр, из которого значение убрали при подготовке модели, в просмотрщике не виден, и в плагине его тоже нет. Те же правила действуют в списке параметров для условий отбора и в поиске по конкретному параметру. Штатная панель свойств прячет ровно эти же поля.

Разбор свойств ограничен по глубине вложенности и по числу узлов на слой, а обход периодически отдаёт управление интерфейсу. Поэтому поиск по тяжёлой модели не подвешивает программу. Полный набор свойств читается только для найденных элементов, а не для всей модели.

## Общий блок «НашеПО»

Контейнер панелей `nashepo` объявлен в этом плагине, но собирает панели всех плагинов. Любой другой плагин может добавить свою панель в этот же блок, указав в манифесте `"container": "nashepo"`. Так все инструменты собираются в одном месте слева.

Вкладка ленты `nashepo_tools` работает так же: каждый плагин добавляет в неё свою группу кнопок.

А вот верхнее меню объединяется только по полю `role`, которое уходит в системное меню окна. Нестандартное значение там рискованно, поэтому у каждого плагина своё меню с собственным названием: **НашеПО · Поиск** и **НашеПО · Проект**.

## Сборка

```sh
npm install
npm run build
```

Сборка попадает в `dist/` и копируется в `docs/`, откуда её публикует GitHub Pages. Отладка — `npm run serve`, проверка типов — `npm run typecheck`.
